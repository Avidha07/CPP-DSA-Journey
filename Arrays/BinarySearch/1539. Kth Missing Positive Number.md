LeetCode 1539 --- Kth Missing Positive Number
Problem
Given a strictly increasing array arr of positive integers and an
integer k, return the k-th positive integer that is missing from the
array.

Example
arr = [2, 3, 4, 7, 11]
k = 5
Answer = 9
The missing positive integers are:
1, 5, 6, 8, 9, 10, 12, ...
The 5th missing positive integer is 9.
1. Key Observation: Count Missing Numbers
At index i, the array contains i + 1 elements.

If no positive integers were missing, the value at index i would be
i + 1. For example:
Index:  0  1  2  3  4
Array:  1  2  3  4  5
But for:
arr = [2, 3, 4, 7, 11]
Index =  0  1  2  3   4
the number of positive integers missing up to arr[i] is:

\(`\boxed{\text{missing}(i) = arr[i] - (i + 1)}`{=tex}\)

Why? There are arr[i] positive integers from 1 through arr[i], but
only i + 1 of them are present in the array. Their difference is the
number missing.
Index `i`   `arr[i]`   Missing count `arr[i] - (i + 1)`
        0          2                                  1
        1          3                                  1
        2          4                                  1
        3          7                                  3
        4         11                                  6
For example, up to 7, the missing numbers are 1, 5, 6, so the
missing count is 3.
2. Why Binary Search Works
As we move right through a strictly increasing array, the missing count
never decreases.

We need to find the first index where the missing count is greater
than or equal to k.

The condition is:

\(arr\[mid\) - (mid + 1) \ge {=tex}k ]
- If missing < k, there are not enough missing numbers yet. Search
  right: low = mid + 1.
- If missing >= k, this index might be the boundary, so search left:
  high = mid - 1.
After the loop, low is the first index whose missing count is at least
k, and high = low - 1.
3. Derivation: Why Do We Return low + k?
This is the main formula. We can derive it instead of memorizing it.
Step 1: Use the final Binary Search boundary
When the loop finishes:

\(`\boxed{low = high + 1}`{=tex}\)

high is the last index before the boundary, where fewer than k
numbers are missing.
Step 2: Count how many numbers are still needed
The number of missing positive integers up to arr[high] is:

\(arr\[high\) - (high + 1) ]

So the number of additional missing integers needed to reach the k-th
missing number is:

k - `\big`{=tex}(arr\[high - (high + 1)\big{=tex}) ]
Step 3: Move forward from arr[high]
Start from arr[high] and add the number of additional integers needed:
\[
```{=tex}
\begin{aligned}
ans &= arr[high] + k - \big(arr[high] - (high + 1)\big)\\
&= arr[high] + k - arr[high] + high + 1\\
&= k + high + 1
\end{aligned}
```
\]
Since low = high + 1:

\(`\boxed{ans = k + low}`{=tex}\)

Therefore, the final statement is:
return low + k;
Important edge case
If the k-th missing number is before the first array element, Binary
Search may finish with:
high = -1
low = 0
We should not access arr[high] in the implementation because arr[-1]
is invalid. The formula low + k handles this case naturally.

For example:
arr = [2, 3, 4, 7, 11]
k = 1
low = 0
answer = low + k = 1
4. Dry Run: arr = [2, 3, 4, 7, 11], k = 5
Initial values:
low = 0
high = 4
`low`   `high`   `mid`   `arr[mid]`   Missing count Decision
    0        4       2            4     `4 - 3 = 1` `1 < 5`, move right
    3        4       3            7     `7 - 4 = 3` `3 < 5`, move right
    4        4       4           11    `11 - 5 = 6` `6 >= 5`, move left
Now low = 4 and high = 3, so the loop ends.
answer = low + k
       = 4 + 5
       = 9
The missing sequence confirms it:
1st missing = 1
2nd missing = 5
3rd missing = 6
4th missing = 8
5th missing = 9
5. C++ Solution
class Solution {
public:
    int findKthPositive(vector<int>& arr, int k) {
        int low = 0;
        int high = arr.size() - 1;

        while (low <= high) {
            int mid = low + (high - low) / 2;

            int missing = arr[mid] - (mid + 1);

            if (missing < k) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }

        return low + k;
    }
};
6. Complexity Analysis
- Time: O(log n) --- Binary Search halves the search range in
  every iteration.
- Extra space: O(1) --- only a constant number of variables are
  used.
7. Pattern to Remember
1. Count missing numbers at index i using arr[i] - (i + 1).
2. Binary Search for the first index where the missing count is at
   least k.
3. At the end, low is the boundary index.
4. Return low + k.
The formula is not magic: it follows from the missing-count formula
and the final Binary Search boundary low = high + 1.
