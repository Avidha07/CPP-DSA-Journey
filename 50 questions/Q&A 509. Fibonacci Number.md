# Fibonacci Number — Interview Questions & Answers

---

# Basic Questions

## 1. Why does the recursive approach become exponential?

In the recursive approach, the same Fibonacci values are calculated multiple times.

For example:

```text
fib(5)
├── fib(4)
│   ├── fib(3)
│   └── fib(2)
└── fib(3)
```

Here, `fib(3)` is calculated again and again.

Because every function call creates two more calls, the total number of calls grows exponentially.

### Time Complexity

```text
O(2^n)
```

---

## 2. What are overlapping subproblems?

Overlapping subproblems occur when the same problem is solved multiple times.

Example:

```text
fib(3)
```

is computed repeatedly in recursion.

Dynamic Programming stores already computed answers to avoid recalculation.

---

## 3. Why is DP faster than recursion?

Dynamic Programming avoids repeated calculations by storing previously computed results.

Instead of solving the same subproblem again:
- DP reuses stored answers.
- This reduces unnecessary recursive calls.

Thus, time complexity improves from:

```text
O(2^n) → O(n)
```

---

## 4. Why can Fibonacci be optimized to O(1) space?

To compute the current Fibonacci number, we only need:
- previous number
- second previous number

We do not need the entire DP array.

So we use only two variables.

Example:

```text
curr = prev1 + prev2
```

This reduces space complexity from:

```text
O(n) → O(1)
```

---

## 5. What is the base condition in Fibonacci recursion?

The base conditions are:

```text
F(0) = 0
F(1) = 1
```

These conditions stop recursive calls from continuing infinitely.

Example:

```java
if(n <= 1)
    return n;
```

# Intermediate Questions

## 1. Difference between Memoization and Tabulation?

### Memoization
- Top-Down approach
- Uses recursion
- Stores answers after computation

### Tabulation
- Bottom-Up approach
- Uses iteration
- Builds answers from smaller subproblems

---

## 2. Why is recursion slower for large inputs?

Recursion becomes slow because:
- Function calls are expensive
- Same values are recalculated multiple times
- Stack memory usage increases

This creates large overhead for big inputs.

---

## 3. Can Fibonacci be solved using iteration only?

Yes.

We can solve Fibonacci using loops without recursion.

Example:
- Store previous two values
- Update them iteratively

This is the most interview-friendly approach.

---

## 4. Why does memoization reduce time complexity?

Memoization stores already computed Fibonacci values.

When the same value is needed again:
- It is directly returned from memory
- No repeated recursion happens

Thus complexity reduces to:

```text
O(n)
```

---

## 5. Why does recursion use stack space?

Every recursive function call is stored in the call stack.

The stack stores:
- local variables
- return addresses
- function states

For Fibonacci recursion:
- Maximum recursive depth becomes `n`

Therefore stack space complexity is:

```text
O(n)
```

# Advanced Questions

## 1. What is Binet’s Formula?

Binet’s Formula is a mathematical formula used to directly calculate Fibonacci numbers.

Formula:

```text
F(n) = [((1 + √5)/2)^n - ((1 - √5)/2)^n] / √5
```

It computes Fibonacci numbers in constant time.

---

## 2. Why can floating-point precision become an issue?

Binet’s Formula uses:
- square roots
- powers
- decimal values

Computers cannot perfectly store floating-point numbers.

For very large `n`:
- small precision errors accumulate
- incorrect answers may occur

---

## 3. Can Fibonacci be solved in O(log n)?

Yes.

Using:
- Matrix Exponentiation
- Fast Doubling Method

we can solve Fibonacci in:

```text
O(log n)
```

time complexity.

---

## 4. How does Matrix Exponentiation work for Fibonacci?

Fibonacci can be represented using matrices:

```text
|1 1|
|1 0|
```

By raising this matrix to power `n`, we can calculate Fibonacci numbers efficiently.

Using Binary Exponentiation:
- matrix multiplication becomes logarithmic

Thus complexity becomes:

```text
O(log n)
```

---

## 5. Why is the precomputed array approach not scalable?

The precomputed approach:
- works only for fixed limits
- requires hardcoded values

Problems:
- cannot handle very large inputs
- memory becomes impractical
- not flexible for changing constraints

Therefore it is not scalable for real-world systems.

# Conclusion

- Recursion is simple but inefficient.
- Dynamic Programming removes repeated work.
- Space optimization improves memory efficiency.
- Matrix Exponentiation gives logarithmic performance.
- Mathematical formulas may face precision issues.
