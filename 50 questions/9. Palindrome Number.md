# Palindrome Number

A palindrome number is a number that reads the same forward and backward.

## Examples

- `121` → Palindrome
- `1331` → Palindrome
- `123` → Not a Palindrome
- `-121` → Not a Palindrome

---

# Problem Statement

Given an integer `x`, return `true` if `x` is a palindrome, otherwise return `false`.

---

# 1. Brute Force Approach (Convert Number to String)

## Idea

- Convert the integer into a string.
- Compare characters from both ends using two pointers.

---

## Brute Force Code

```cpp
class Solution {
public:
    bool isPalindrome(int x) {

        // Negative numbers are not palindrome
        if(x < 0)
            return false;

        string s = to_string(x);

        int left = 0;
        int right = s.length() - 1;

        while(left < right)
        {
            if(s[left] != s[right])
                return false;

            left++;
            right--;
        }

        return true;
    }
};
```

---

## Dry Run

### Input

```text
x = 121
```

### Initial State

```text
s = "121"
left = 0
right = 2
```

### Iteration 1

```text
s[left] = '1'
s[right] = '1'

Match found
left++
right--
```

### Updated

```text
left = 1
right = 1
```

Loop stops.

### Final Output

```text
true
```

---

## Time Complexity

- **O(n)**  
  (`n` = number of digits)

## Space Complexity

- **O(n)**  
  Extra string storage required.

---

# 2. Reverse Entire Number Approach

## Idea

- Reverse the given number mathematically.
- Compare original number with reversed number.

---

## Code

```cpp
class Solution {
public:
    bool isPalindrome(int x) {

        if(x < 0)
            return false;

        int n = x;
        long long reverse = 0;

        while(n > 0)
        {
            int digit = n % 10;
            reverse = reverse * 10 + digit;
            n /= 10;
        }

        return x == reverse;
    }
};
```

---

## Dry Run

### Input

```text
x = 121
```

### Iteration 1

```text
digit = 1
reverse = 1
n = 12
```

### Iteration 2

```text
digit = 2
reverse = 12
n = 1
```

### Iteration 3

```text
digit = 1
reverse = 121
n = 0
```

### Final Check

```text
121 == 121 → true
```

---

## Time Complexity

- **O(log10(n))**

## Space Complexity

- **O(1)**

---

# 3. Optimal Approach (Reverse Half Number)

## Idea

Instead of reversing the complete number:

- Reverse only half of the digits.
- Compare both halves.

This avoids overflow problems.

---

## Optimal Code

```cpp
class Solution {
public:
    bool isPalindrome(int x) {

        if(x < 0 || (x % 10 == 0 && x != 0))
            return false;

        int reversedHalf = 0;

        while(x > reversedHalf)
        {
            reversedHalf = reversedHalf * 10 + x % 10;
            x /= 10;
        }

        return (x == reversedHalf) ||
               (x == reversedHalf / 10);
    }
};
```

---

## Dry Run

### Input

```text
x = 1221
```

### Iteration 1

```text
reversedHalf = 1
x = 122
```

### Iteration 2

```text
reversedHalf = 12
x = 12
```

### Final Check

```text
12 == 12 → true
```

---

# Time Complexity Comparison

| Approach | Time Complexity | Space Complexity |
|---|---|---|
| String Conversion | O(n) | O(n) |
| Reverse Entire Number | O(log10(n)) | O(1) |
| Reverse Half Number (Optimal) | O(log10(n)) | O(1) |

# Edge Cases

## Negative Number

```text
x = -121
```

Negative numbers are never palindrome.

---

## Number Ending with Zero

```text
x = 10
```

Cannot be palindrome because reverse becomes `01`.

---

## Single Digit Number

```text
x = 7
```

Always palindrome.

---

# Why Optimal Approach is Better

- Avoids integer overflow.
- Reverses only half of the number.
- More efficient for large integers.
- Uses constant space.

---

# Interview Questions with Answers

## 1. Why are negative numbers not palindrome?

Because the negative sign `-` appears only at the beginning.

Example:

```text
-121 != 121-
```

---

## 2. Why do we use `% 10`?

To extract the last digit of a number.

Example:

```text
123 % 10 = 3
```

---

## 3. Why do we use `/= 10`?

To remove the last digit.

Example:

```text
123 / 10 = 12
```

---

## 4. Why can reversing the full number cause overflow?

If reversed value exceeds integer range:

```text
INT_MAX = 2147483647
```

overflow may happen.

---

## 5. Why does reversing only half solve overflow?

Because only half of the digits are reversed, the number remains smaller.

---

## 6. Why check:

```cpp
x == reversedHalf / 10
```

For odd-length numbers.

Example:

```text
121
```

Middle digit does not matter.

---

## 7. What is the stopping condition in optimal approach?

```cpp
while(x > reversedHalf)
```

Because after half reversal:

- either both halves become equal
- or reversed half becomes larger

---

## 8. Can this problem be solved recursively?

Yes, but recursion uses extra stack space.

---

## 9. Which approach is most preferred in interviews?

Reverse Half Number Approach.

Because:

- Optimal
- Avoids overflow
- Constant space

---

## 10. What type of problem is this?

- Mathematics
- Number Manipulation
- Two Pointer Logic (conceptually)
